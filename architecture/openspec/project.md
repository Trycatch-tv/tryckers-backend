# Tryckers Backend OpenSpec Project

## Project Purpose

Tryckers backend provides the API, business rules, persistence, and authentication foundation for the Tryckers ecosystem.

## Architecture Baseline

- Layered Modular Monolith.
- Gin + Go.
- GORM + PostgreSQL.
- REST under `/api/v1`.
- DTO-based API contracts.
- Service + Repository pattern.
- JWT authentication and bcrypt password hashing.

## Change Principles

- Every meaningful change should be expressed as a vertical slice.
- Keep implementation focused on one capability.
- Document frontend impact when API contracts change.
- Apply Supabase database changes through the Supabase MCP server.
- Leave pending changes uncommitted for review when generated by `vs-agent`.

## Review Expectations

Reviewers should check:

- Correct architecture layer boundaries.
- Complete DTO and API contract documentation.
- Migration safety.
- Test coverage proportional to risk.
- Roadmap and tag updates after merge.
